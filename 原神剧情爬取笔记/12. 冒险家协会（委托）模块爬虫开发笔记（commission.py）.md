## 冒险家协会（委托）模块爬虫开发笔记（`commission.py`）

> 本文档记录了《原神》观测枢冒险家协会（委托）爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`commission.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有冒险家协会相关条目，包括：
- 每日委托、突发事件、声望任务、冒险之证等各类委托
- 委托名称、类型（委托类型）、区域、有无成就
- 简介（列表页 `summary` 字段）
- 详情页中的完整任务描述、触发条件、任务过程、剧情对话、相关表格等

**输出**：每个委托保存为一个 `.txt` 文本文件，存放在 `data/cleaned/commission/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的委托 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 委托列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=55`（冒险家协会频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "冒险家协会"
      └── list[] → 每个委托条目
          ├── content_id: 委托 ID
          ├── title: 委托名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 委托详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={委托ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 常见模块与组件：
    - `base_info`：键值对基本信息（如触发条件）。
    - `collapse_panel` / `rich_base_info`：富文本内容（任务过程、图文说明）。
    - `multi_table`：表格数据（情报任务列表、奖励列表等）。
    - `interactive_dialogue`：剧情对话树（玩家选项与 NPC 对话）。
    - `map_desc`：地图图片（通常无文本，忽略）。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含委托的分类筛选标签：

```json
{
  "c_55": {
    "filter": {
      "text": "[\"委托类型/每日委托\", \"区域/挪德卡莱\", \"有无成就/无\"]"
    }
  }
}
```

解析后得到：
- `commission_type`: "每日委托"
- `region`: "挪德卡莱"
- `has_achievement`: "无"

#### 4.2 详情页模块解析

| 组件 ID                | 模块名示例          | 提取内容         | 是否提取                       |
| :--------------------- | :------------------ | :--------------- | :----------------------------- |
| `base_info`            | 基础信息            | 触发条件等键值对 | ✅ 提取（作为“基本信息”）       |
| `collapse_panel`       | 任务过程 / 地图说明 | 富文本描述       | ✅ 提取（模块名作标题）         |
| `multi_table`          | 情报任务 / 奖励     | 表格数据         | ✅ 提取（表头与行拼接为文本）   |
| `interactive_dialogue` | 剧情对话            | 对话与选项       | ✅ 提取（选项以 `[选项]` 标记） |
| `map_desc`             | 地图展示            | 地图图片         | ❌ 忽略（无文本内容）           |

**特殊过滤**：
- **任务奖励模块**（`module_name == "任务奖励"`）：包含大量冒险等阶对应原石/摩拉/矿物的表格，对剧情向 RAG 价值极低，**直接跳过**。

#### 4.3 对话树解析（`interactive_dialogue`）

- 数据结构：`list` 数组，每个元素包含 `root_id`、`child_ids`（子节点映射）、`contents`（节点内容字典）。
- 递归遍历所有节点，提取 `option` 和 `dialogue` 字段。
- 清洗时使用 `clean_html_to_text`，并**压缩内部所有换行符为空格**，确保每条对话/选项显示在同一行。
- 不同条目之间用**空行分隔**，提高可读性。
- 输出格式示例：
  ```
  [选项] 旅行者：你又有什么主意了？
  
  卡兹加： 平时霍莱都能吃完一整盆果子，吃完之后能疯玩一整天。
  
  卡兹加： 现在它一盆水果只能吃一半多…
  ```

#### 4.4 表格提取（`multi_table`）

- 解析 `tables[].header` 和 `tables[].row`，将每个单元格清洗后拼接为文本行。
- 使用 `|` 分隔列，便于视觉区分。


### 五、输出格式

每个委托保存为一个 `.txt` 文件，文件名使用委托名称（非法字符替换为 `_`）。

**内容结构示例**（以“铁亦无用”为例）：

```

委托类型：每日委托
区域：挪德卡莱
有无成就：无
简介：挪德卡莱每日委托 铁亦无用

【基本信息】
触发条件：解锁挪德卡莱每日委托

【任务过程】
愚人众似乎正操纵着各个型号的「巡陆艇」四处作乱，必须立刻阻止他们，并且完全摧毀巡陆艇。
击败所有敌人

【剧情对话】
沙尔梅：既然您把它们都拿来了，那我也该开始工作啦，这可是一份庞大的工作量啊。
沙尔梅：这些东西请您收下吧。再次感谢您帮忙，荣誉高级研究员。
沙尔梅：唉，院里什么时候才能给我派个帮手过来…

```


### 六、核心函数说明

| 函数                                                   | 职责                                                         |
| :----------------------------------------------------- | :----------------------------------------------------------- |
| `get_commission_list()`                                | 获取所有委托的 ID、名称、简介和分类标签（委托类型/区域/有无成就）。 |
| `parse_commission_ext(ext_str)`                        | 解析 `ext.filter.text` 中的 JSON 数组，提取委托类型、区域、有无成就。 |
| `parse_interactive_dialogue(comp_data)`                | 递归解析对话树，返回格式化后的纯文本对话流。                 |
| `parse_commission_detail(page_data)`                   | 遍历 `modules`，根据组件类型提取文本，并跳过“任务奖励”模块。 |
| `generate_commission_content(commission_info, detail)` | 将基本信息与各模块内容格式化为纯文本内容。                   |
| `process_commission(commission, output_dir)`           | 请求详情 API，解析并保存单个委托。                           |
| `run()`                                                | 主流程，控制爬取范围和增量逻辑。                             |

### 十、注意事项

1. **跳过任务奖励模块**：`module_name == "任务奖励"` 的模块包含大量数值表格，对剧情向 RAG 价值低且增加文件体积，直接跳过。
2. **对话换行处理**：`parse_interactive_dialogue` 中通过 `" ".join(clean.split())` 压缩所有内部换行，防止对话被截断为多行，确保每条对话/选项在一行内显示。
3. **多模块同名处理**：如果多个模块名称相同（如多个“任务过程”），解析结果会使用相同 key，并自动追加内容（用空行分隔）。
4. **表格提取**：`multi_table` 的 `row` 中每个 cell 均为 HTML，清洗后可能包含换行，同样会压缩，但表格结构仍保留。
5. **地图说明**：`map_desc` 组件仅含地图图片 URL，无文本，故忽略。
6. **文件名清洗**：委托名称可能包含特殊字符，使用 `safe_filename` 替换为下划线。
7. **空内容过滤**：若委托详情页无任何可提取文本（如仅有图片），该委托将被跳过，不生成文件。


### 十一、与已有模块的对比

| 特性     | 委托模块                 | 任务模块（`task.py`）                | 动物模块（`animal.py`） |
| :------- | :----------------------- | :----------------------------------- | :---------------------- |
| 频道 ID  | `55`                     | `3`                                  | `49`                    |
| 分类标签 | 委托类型、区域、有无成就 | 任务类型、任务区域、版本号           | 动物类型、是否可捕获    |
| 列表结构 | 扁平列表                 | 嵌套子任务（`tab` → `module_group`） | 扁平列表                |
| 核心内容 | 任务描述、过程、对话     | 子任务 + 对话树                      | 背景故事                |
| 特有组件 | `multi_table`（表格）    | `interactive_dialogue`               | `good_desc`             |
| 跳过内容 | 任务奖励                 | 地图说明、任务奖励                   | 基础信息、攻略方法      |
| 输出粒度 | 每个委托一个文件         | 每个子任务一个文件                   | 每个动物一个文件        |


### 十二、后续优化方向

1. **更精细的表格解析**：当前 `multi_table` 直接将所有行拼接为文本，未来可考虑生成 Markdown 表格，或提取结构化数据（如奖励列表）。
2. **对话分支的上下文保留**：当前仅平铺对话，未来可加入缩进或标记，区分不同分支。
3. **支持增量更新**：通过内容哈希检测变更，避免手动删除 ID。
4. **多线程并发**：使用线程池加速爬取（需控制并发数避免风控）。
5. **命令行参数**：支持通过 `argparse` 指定 `test_limit` 或特定的委托 ID 列表。
