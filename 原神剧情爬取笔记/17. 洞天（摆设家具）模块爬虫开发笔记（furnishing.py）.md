## 洞天（摆设/家具）模块爬虫开发笔记（`furnishing.py`）

> 本文档记录了《原神》观测枢洞天（摆设/家具）爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`furnishing.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有洞天摆设/家具的详细信息，包括：
- 摆设名称、区域（室内/室外）、类型（墙饰/摆件/地貌/套装等）
- 品质（二星/三星/四星/五星）
- 摆设获取方式、图纸获取方式
- 物品描述（核心文本，包含背景/文化叙述）
- 获取途径（制作/宝箱/活动等）
- 相关套装（所属好感套装名称）

**输出**：每个摆设保存为一个 `.txt` 文本文件，存放在 `data/cleaned/furnishing/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的摆设 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 摆设列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=130`（洞天频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "洞天"
      └── list[] → 每个摆设条目
          ├── content_id: 摆设 ID
          ├── title: 摆设名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 摆设详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={摆设ID}`, `lang=zh-cn`
- **核心模块**:
  - `物品描述`（`good_desc`）：包含摆设的叙述文本和获取途径。
  - `基础属性`（`rich_base_info`）：包含洞天仙力、摆放区域、分类、相关套装等。
  - `基础信息`（`cave_base_info`）：包含名称、图标、制作材料（跳过）。
  - `地图说明`（`map_desc`）：纯图片（跳过）。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含摆设的分类筛选标签：

```json
{
  "c_130": {
    "filter": {
      "text": "[\"区域/室内\", \"类型/墙饰\", \"品质/三星\", \"摆设获取方式/制作摆设获取\", \"图纸获取方式/奇馈的宝箱获得\"]"
    }
  }
}
```

解析后得到：
- `region`: "室内"
- `type`: "墙饰"
- `quality`: "三星"
- `obtain_method`: "制作摆设获取"
- `blueprint_obtain`: "奇馈的宝箱获得"

#### 4.2 详情页模块解析

| 模块名   | 组件 ID          | 提取内容                    | 是否提取 |
| :------- | :--------------- | :-------------------------- | :------- |
| 物品描述 | `good_desc`      | `rich_text`（物品描述文本） | ✅ 核心   |
| 物品描述 | `good_desc`      | `attr`（获取途径）          | ✅        |
| 基础属性 | `rich_base_info` | 相关套装                    | ✅        |
| 基础信息 | `cave_base_info` | 制作材料                    | ❌ 跳过   |
| 地图说明 | `map_desc`       | 图片                        | ❌ 跳过   |

#### 4.3 物品描述解析

`good_desc` 模块的数据结构：

```json
{
  "component_id": "good_desc",
  "data": {
    "rich_text": "<p>常见于皮拉米达城之内的旗帜...</p>",
    "attr": [
      {"key": "摆设获取途径：", "value": ["<p>制作</p>"]},
      {"key": "摆设图纸获取途径：", "value": ["<p>挪德卡莱地区奇馈宝箱奖励</p>"]}
    ]
  }
}
```

#### 4.4 相关套装提取

`rich_base_info` 模块的数据结构：

```json
{
  "component_id": "rich_base_info",
  "data": {
    "list": [
      {"key": "相关套装\t", "value": ["<p>「烟谜主」的安适【赠礼】</p>"]}
    ]
  }
}
```

提取 `key` 中包含“套装”的条目。


### 五、输出格式

每个摆设保存为一个 `.txt` 文件，文件名使用摆设名称（非法字符替换为 `_`）。

**内容结构示例**（以“「皮拉米达之帜」”为例）：

```
摆设名称：「皮拉米达之帜」
区域：室内
类型：墙饰
品质：三星
摆设获取方式：制作摆设获取
图纸获取方式：奇馈的宝箱获得
相关套装：暂无

【物品描述】
常见于皮拉米达城之内的旗帜，其上绘有执灯人的灯塔图标，展现了执灯人在黑夜中永执明灯，守望未来的意志。

【获取途径】
摆设获取途径：制作
摆设图纸获取途径：挪德卡莱地区奇馈宝箱奖励
```


### 六、核心函数说明

| 函数                                         | 职责                                                       |
| :------------------------------------------- | :--------------------------------------------------------- |
| `parse_furnishing_ext(ext_str)`              | 解析 `ext.filter.text` 中的 JSON 数组，提取 5 个分类标签。 |
| `get_furnishing_list()`                      | 获取所有摆设的 ID、名称和分类标签。                        |
| `parse_furnishing_detail(page_data)`         | 遍历 `modules`，提取物品描述、获取途径、相关套装。         |
| `generate_furnishing_content(info, detail)`  | 将摆设信息与详情数据格式化为纯文本内容。                   |
| `process_furnishing(furnishing, output_dir)` | 请求详情 API，解析并保存单个摆设。                         |
| `run()`                                      | 主流程，控制爬取范围和增量逻辑。                           |

### 十、注意事项

1. **文件名清洗**：摆设名称可能包含特殊字符（如 `「」`、`·`、制表符、空格等），`safe_filename` 会去除首尾空白并替换所有空白字符为下划线。
2. **无描述则跳过**：若摆设没有物品描述（`good_desc.rich_text` 为空），视为无剧情价值，该摆设被跳过。
3. **获取途径保留**：`good_desc.attr` 中的获取途径作为补充信息保留。
4. **套装可能为空**：部分摆设没有相关套装，`related_sets` 字段保持空字符串。
5. **`list: null` 防御**：`rich_base_info` 的 `list` 字段可能为 `null`，代码已增加防御性检查。
6. **制作材料跳过**：`cave_base_info` 中的制作材料为纯数值，已跳过。

### 十二、后续优化方向

1. **制作材料提取**：目前 `cave_base_info` 中的制作材料已跳过，未来可根据需要添加为补充信息。
2. **套装关联展开**：相关套装目前只是名称，未来可爬取套装详情，建立“摆设 → 套装”的关联索引。
3. **支持分类过滤**：通过命令行参数指定只爬取特定区域（室内/室外）或特定类型的摆设。
4. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
