## 动物模块爬虫开发笔记（`animal.py`）

> 本文档记录了《原神》观测枢动物爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`animal.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有动物的详细信息，包括：
- 动物名称、动物类型（禽鸟/走兽/游鱼/其他）
- 是否可捕获（是/否）
- 简介（列表页 `summary` 字段）
- 背景故事（`good_desc` 模块）

**输出**：每个动物保存为一个 `.txt` 文本文件，存放在 `data/cleaned/animal/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的动物 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 动物列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=49`（动物频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "动物"
      └── list[] → 每个动物条目
          ├── content_id: 动物 ID
          ├── title: 动物名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 动物详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={动物ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 关键模块：
    - `monster_base_info`：基础信息（攻略方法、掉落物、技能图片等）。
    - `good_desc`：背景故事（核心）。
    - `collapse_panel`：攻略方法（本模块跳过）。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含动物的分类筛选标签：

```json
{
  "c_49": {
    "filter": {
      "text": "[\"动物类型/其他\", \"是否可捕获/是\"]"
    }
  }
}
```

解析后得到：
- `animal_type`: "其他"
- `can_capture`: "是"

#### 4.2 详情页模块解析

| 模块名 | `component_id` | 提取内容 | 是否提取 |
| :--- | :--- | :--- | :--- |
| 基础信息 | `monster_base_info` | 攻略方法、掉落物、技能图片 | ❌ 跳过 |
| 背景故事 | `good_desc` | 动物的背景/介绍文本 | ✅ 提取（核心） |
| 攻略方法 | `collapse_panel` | 战斗/捕捉机制描述 | ❌ 跳过 |

#### 4.3 背景故事结构

`good_desc` 模块包含动物的背景介绍文本：

```json
{
  "component_id": "good_desc",
  "data": {
    "rich_text": "<p>常在湿地出没的小小青蛙。</p><p>潮湿地带十分常见的小动物...</p>",
    "attr": [
      {"key": "备注：", "value": ["<p>出现在池塘或湖泊边缘...</p>"]}
    ]
  }
}
```

**提取策略**：提取 `rich_text` 字段，使用 `clean_html_to_text` 清洗。若存在 `attr` 中的备注信息，可一并提取（当前实现仅提取 `rich_text`）。

#### 4.4 跳过模块

| 模块名 | `component_id` | 跳过原因 |
| :--- | :--- | :--- |
| 基础信息 | `monster_base_info` | 仅包含攻略方法、掉落物链接、技能动图，无文本价值 |
| 攻略方法 | `collapse_panel` | 纯机制描述，对剧情向 RAG 帮助有限 |


### 五、输出格式

每个动物保存为一个 `.txt` 文件，文件名使用动物名称（非法字符替换为 `_`）。

**内容结构示例**：

```
动物名称：丛林树蛙
动物类型：其他
是否可捕获：是
简介：丛林树蛙

【背景故事】
常在湿地出没的小小青蛙。
潮湿地带十分常见的小动物，身上会分泌奇特的粘液，具有多种药用用途。树蛙适应丛林中的生活。
据说有些树蛙可以在丛林间滑翔。根据研究，其原理与风之翼有不少相似之处。
```


### 六、核心函数说明

| 函数 | 职责 |
| :--- | :--- |
| `get_animal_list()` | 获取所有动物的 ID、名称、简介和分类标签（动物类型/是否可捕获）。 |
| `parse_filter_tags(filter_text)` | 解析 `ext.filter.text` 中的 JSON 数组，提取动物类型、是否可捕获。 |
| `parse_animal_detail(page_data)` | 解析详情页 JSON，提取背景故事。 |
| `generate_animal_content(animal_info, detail)` | 将解析结果格式化为纯文本内容。 |
| `process_animal(animal_info, output_dir)` | 请求详情 API，解析并保存单个动物。 |
| `run()` | 主流程，控制爬取范围和增量逻辑。 |

### 十、注意事项

1. **跳过基础信息**：`monster_base_info` 模块中包含攻略方法、掉落物链接和技能动图，均为非文本内容，已跳过。
2. **跳过攻略方法**：`collapse_panel` 模块在动物详情中通常为空或包含捕捉机制描述，对 RAG 语料库价值有限，已跳过。
3. **背景故事识别**：通过 `module_name == "背景故事"` 定位模块，比依赖 `component_id` 更稳定。
4. **空内容过滤**：若动物没有背景故事（`good_desc` 为空或仅有空白内容），该动物将被跳过，不生成文件。
5. **文件名清洗**：动物名称可能包含特殊字符，使用 `safe_filename` 替换为下划线。

### 十二、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围和模式。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
4. **备注信息提取**：当前仅提取 `rich_text`，未来可考虑提取 `attr` 中的备注信息。
