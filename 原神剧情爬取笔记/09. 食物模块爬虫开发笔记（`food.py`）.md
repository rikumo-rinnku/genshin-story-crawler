## 食物模块爬虫开发笔记（`food.py`）

> 本文档记录了《原神》观测枢食物爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`food.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有食物的详细信息，包括：
- 食物名称、食物类型（回复类/复活类/体力类/攻击类/防御类/暴击类/生命上限/治疗加成/合成药剂/特殊食物）
- 星级（一星至五星/其他）、获取方式（NPC购买/任务获取/宝箱获取/其他）
- 是否产出特殊料理（是/否）
- 各变体的描述、使用效果、获得方式、食谱获得、加工材料

**输出**：每个食物保存为一个 `.txt` 文本文件，存放在 `data/cleaned/food/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的食物 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 食物列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=21`（食物频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "食物"
      └── list[] → 每个食物条目
          ├── content_id: 食物 ID
          ├── title: 食物名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 食物详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={食物ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 关键模块：
    - `material_base_info`：每个变体的详细信息（奇怪版/普通版/美味版/特殊料理）。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含食物的分类标签：

```json
{
  "c_21": {
    "filter": {
      "text": "[\"食物类型/复活类\", \"食物星级/三星\", \"食物获取方式/任务获取\", \"是否产出特殊料理/是\"]"
    }
  }
}
```

解析后得到：
- `food_type`: "复活类"
- `star`: "三星"
- `obtain`: "任务获取"
- `has_special`: "是"

#### 4.2 详情页变体解析

一个食物条目可能包含多个 `material_base_info` 模块，每个模块代表一个变体：

| 变体类型 | `name` 特征                 | 示例                 |
| :------- | :-------------------------- | :------------------- |
| 奇怪版   | 以 "奇怪" 开头              | `"奇怪薄荷泡泡糖"`   |
| 普通版   | 无特殊前缀                  | `"薄荷泡泡糖"`       |
| 美味版   | 以 "美味的" 开头            | `"美味的薄荷泡泡糖"` |
| 特殊料理 | 包含 "特殊"、"特色"、"专属" | `"解闷泡泡糖"`       |

**每个变体的数据结构**：

```json
{
  "name": "薄荷泡泡糖",
  "star": 3,
  "materials": {
    "key": "加工材料",
    "value": "<span>薄荷</span>*2 <span>落落莓</span>*2 <span>糖</span>*1"
  },
  "attr": [
    {"key": "描述", "value": ["<p>有弹性的柔软糖果...</p>"]},
    {"key": "使用效果", "value": ["<p>复苏选中的角色...</p>"]},
    {"key": "获得方式", "value": ["<p>成功烹饪薄荷泡泡糖</p>"]},
    {"key": "食谱获得", "value": ["<p>完成：洛恩——传说任务...</p>"]}
  ]
}
```

#### 4.3 加工材料提取（特殊处理）

加工材料的 HTML 中，材料名称和数量被多个 `<span>` 标签分隔：

```html
<span>薄荷</span>*2 <span>落落莓</span>*2 <span>糖</span>*1
```

直接使用 `clean_html_to_text` 会用换行分隔，导致：
```
薄荷
*2
落落莓
*2
糖
*1
```

**解决方案**：使用 `extract_materials_text` 函数，先提取纯文本并用空格分隔，再将空格替换为顿号：

```python
def extract_materials_text(html: str) -> str:
    soup = BeautifulSoup(html, 'lxml')
    text = soup.get_text(separator=' ', strip=True)
    text = re.sub(r'\s+', ' ', text).strip()
    if text:
        parts = text.split()
        return "、".join(parts)
    return ""
```

输出：`"薄荷*2、落落莓*2、糖*1"`

### 六、核心函数说明

| 函数                                         | 职责                                                         |
| :------------------------------------------- | :----------------------------------------------------------- |
| `get_food_list()`                            | 获取所有食物的 ID、名称、简介和分类标签（类型/星级/获取方式/是否特殊料理）。 |

### 十、注意事项

1. **变体识别**：一个食物条目可能包含多个 `material_base_info` 模块，需全部提取。变体类型通过 `name` 字段判断（以"奇怪"开头、以"美味的"开头、包含"特殊"/"特色"/"专属"）。
2. **加工材料换行问题**：`clean_html_to_text` 会错误地将材料拆成多行，需使用 `extract_materials_text` 单独处理。
3. **空内容过滤**：只有至少有一个有效文本字段（描述/效果/获得方式/食谱/材料）的变体才会保留。
4. **星级重复**：详情页的 `star` 与列表页 `ext` 中的星级重复，已在列表提取，详情页的 `star` 字段不单独使用。
5. **特殊料理判断**：特殊料理的识别依赖 `name` 中的关键词（"特殊"、"特色"、"专属"），并非所有有特殊料理标志的食物都一定有特殊料理变体。
6. **图片链接舍弃**：`img` 字段仅包含图片链接，无文本价值，已跳过。
7. **空的 `collapse_panel`**：部分食物详情页包含空的 `collapse_panel` 模块，已通过空值判断跳过。

### 十二、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围和模式。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
4. **变体合并优化**：如果多个变体的内容完全相同（仅名称不同），可考虑合并输出。
5. **材料链接解析**：当前仅提取加工材料的纯文本，未来可考虑提取材料 ID 建立关联。
