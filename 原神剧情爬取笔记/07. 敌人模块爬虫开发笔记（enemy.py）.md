## 敌人模块爬虫开发笔记（`enemy.py`）

> 本文档记录了《原神》观测枢敌人爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`enemy.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有敌人的详细信息，包括：
- 敌人名称、类型（BOSS/精英/普通）、元素（火/水/雷/冰/岩/草/风/无）、攻击方式（近战/远程/混合）
- 简介（列表页 `summary` 字段）
- 背景故事（`good_desc` 模块，含折叠面板展开）
- 位置信息（`timeline_base_info` 模块，若存在）

**输出**：每个敌人保存为一个 `.txt` 文本文件，存放在 `data/cleaned/enemy/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的敌人 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 敌人列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=6`（敌人频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "敌人"
      └── list[] → 每个敌人条目
          ├── content_id: 敌人 ID
          ├── title: 敌人名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 敌人详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={敌人ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 关键模块：
    - `monster_base_info`：基础信息（元素、攻击方式等）。
    - `good_desc`：背景故事（含折叠面板）。
    - `timeline_base_info`：位置导览（部分敌人有）。
    - `collapse_panel`：攻略方法（本模块跳过）。
    - `equipment_growth_info`：数据参考（本模块跳过）。
    - `map_desc`：立绘展示（本模块跳过）。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含敌人的分类筛选标签：

```json
{
  "c_6": {
    "filter": {
      "text": "[\"类型/BOSS\", \"元素/火\", \"元素/雷\", \"攻击方式/混合\"]"
    }
  }
}
```

解析后得到：
- `type`: "BOSS"
- `elements`: ["火", "雷"]
- `attack_types`: ["混合"]

#### 4.2 详情页模块解析

| 模块名   | `component_id`          | 提取内容                       | 是否提取         |
| :------- | :---------------------- | :----------------------------- | :--------------- |
| 基础信息 | `monster_base_info`     | 元素、攻击方式（纯文本）       | ✅ 提取           |
| 背景故事 | `good_desc`             | 完整背景故事（含折叠面板展开） | ✅ 提取（核心）   |
| 位置导览 | `timeline_base_info`    | 位置描述（纯文本）             | ✅ 提取（若存在） |
| 攻略方法 | `collapse_panel`        | 战斗机制描述                   | ❌ 跳过           |
| 数据参考 | `equipment_growth_info` | 生命值、抗性等数值             | ❌ 跳过           |
| 立绘展示 | `map_desc`              | 立绘图片链接                   | ❌ 跳过           |

#### 4.3 折叠面板展开（核心难点）

敌人模块的 `good_desc` 中大量使用 `<details>` 标签存放扩展故事内容，例如「多托雷」的「异质的树髓」三段故事。若直接使用 `clean_html_to_text`，这些内容会被完全丢弃。

**解决方案**：编写 `expand_details_in_html` 函数，在清洗前对 HTML 进行预处理：

1. 使用 BeautifulSoup 解析 HTML。
2. 递归遍历所有 `<details>` 标签。
3. 提取 `<summary>` 作为小标题。
4. 提取 `div[data-type="detailsContent"]` 作为内容。
5. 将 `<details>` 替换为 `标题 + 内容` 的普通 HTML 结构。
6. 递归处理嵌套的 `<details>`（确保完全展开）。

#### 4.4 位置信息解析（特殊处理）

位置信息的 `key` 值不稳定，不同敌人使用的键名不同：

| 敌人            | `key` 值         |
| :-------------- | :--------------- |
| 「多托雷」      | `"位置简述"`     |
| 「丘尔德里克」  | `"大世界"`       |
| 「守望者·堕天」 | `""`（空字符串） |

**解决方案**：不依赖 `key` 值，而是通过 `module_name == "位置导览"` 定位模块，然后提取该模块下所有 `attr.value` 的文本内容。

```python
# 稳定可靠的方式
for module in modules:
    if module.get("name") == "位置导览":
        # 提取所有 attr.value
        ...

# 不可靠的方式（已弃用）
if "位置" in key:  # 会遗漏 key 为空字符串的情况
    ...
```

#### 4.5 跳过模块识别

采用 `module_name` 匹配替代 `component_id` 匹配，更具稳定性：

| 模块名                                | 处理方式           |
| :------------------------------------ | :----------------- |
| `"背景故事"`                          | 提取并展开折叠面板 |
| `"位置导览"`                          | 提取位置信息       |
| 其他（`"攻略方法"`、`"数据参考"` 等） | 跳过               |


### 五、输出格式

每个敌人保存为一个 `.txt` 文件，文件名使用敌人名称（非法字符替换为 `_`）。

**内容结构示例**：

```
敌人名称：守望者·堕天
类型：BOSS
元素：火、水、雷、冰、岩
攻击方式：混合
简介：开眼者·世界望楼之守望

【背景故事】
原初的大能者流溢而出的影之造物，曾居于高天之上的守望者，终因开眼而堕入尘世。
守望者只应沉默地于世界之柱殿守望，一切逾越规则的探求，皆是与谋求世界破灭等同的不赦之罪。
身为世界望楼的统权，执掌其造主所赋予的纠正一切「革新进化之事」的权柄。在历经百千劫的无明后，终于选择开眼直面世界的谎言与真实，却也因此违背了造主的意志。
守望者不知晓那位离去的主人因何离去，唯有永恒的惩罚依然驻留在凝滞的隙间…

【位置信息】
位于风息山-荆夫港一北的区域。该区域只有一个锚点，直达Boss区域。
```

**输出规范**：
- 背景故事保留段落换行，保持可读性。
- 位置信息使用 `" ".join(text.split())` 压缩多余换行，确保句子连贯（对 LLM 阅读更友好）。


### 六、核心函数说明

| 函数                                         | 职责                                                         |
| :------------------------------------------- | :----------------------------------------------------------- |
| `get_enemy_list()`                           | 获取所有敌人的 ID、名称、简介和分类标签（类型/元素/攻击方式）。 |
| `parse_filter_tags(filter_text)`             | 解析 `ext.filter.text` 中的 JSON 数组，提取类型、元素、攻击方式。 |
| `expand_details_in_html(html)`               | 递归展开所有 `<details>` 折叠面板，确保内部文本被提取。      |
| `parse_enemy_detail(page_data)`              | 解析详情页 JSON，提取背景故事和位置信息。                    |
| `generate_enemy_content(enemy_info, detail)` | 将解析结果格式化为纯文本内容（背景故事保留换行，位置信息压缩空白）。 |
| `process_enemy(enemy_info, output_dir)`      | 请求详情 API，解析并保存单个敌人。                           |
| `run()`                                      | 主流程，控制爬取范围和增量逻辑。                             |

### 十、注意事项

1. **折叠面板展开**：敌人模块的 `good_desc` 包含 `<details>` 标签，必须使用 `expand_details_in_html` 展开后再清洗，否则会丢失大量文本（如「多托雷」的「异质的树髓」三段故事）。
2. **位置信息解析**：不要依赖 `key` 值（如 `"位置简述"` 或 `"大世界"`），因为有的敌人 `key` 为空字符串。应通过 `module_name == "位置导览"` 定位模块。
3. **位置信息空白压缩**：`clean_html_to_text` 会将内联标签拆成多行，导致位置信息句子破碎。在 `generate_enemy_content` 中使用 `" ".join(text.split())` 压缩空白，保证句子连贯。
4. **模块名匹配优先**：优先使用 `module_name` 而非 `component_id` 来识别模块（如 `"背景故事"`、`"位置导览"`），因为模块名在编辑器中是固定的，而 `component_id` 可能在不同模块间重复。
5. **跳过内容**：攻略方法（`collapse_panel`）、数据参考（`equipment_growth_info`）、立绘展示（`map_desc`）均被跳过，原因如下：
   - 攻略方法包含大量游戏机制描述，对剧情向 RAG 帮助有限。
   - 数据参考为纯数值，无文本语义价值。
   - 立绘展示仅有图片链接，无文本信息。
6. **网络超时**：如遇 SSL 超时，可检查网络连接或增加 `timeout` 参数。


### 十一、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围和模式。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
4. **折叠面板展开迁移**：如果未来有更多模块需要展开折叠面板，可将 `expand_details_in_html` 迁移到 `src/core/parser.py` 作为公共函数。
5. **位置信息结构化**：目前位置信息是纯文本，未来可考虑提取坐标或锚点名称等结构化数据。
