## 《原神》角色剧情爬虫开发笔记（角色模块）

> 本文档总结了从零开始构建《原神》角色剧情爬虫的完整过程，包括API分析、模块化设计、增量爬取、特殊角色处理等，适用于后续维护和扩展。

---

### 一、项目目标

从米哈游观测枢 Wiki 中爬取所有角色的剧情文本（基础信息、角色描述、配音展示、角色登场等），保存为结构化的文本文件，供 RAG 知识库使用。要求支持增量爬取、缺失标记、特殊角色（旅行者）合并处理。

---

### 二、核心技术栈

| 类别 | 工具 | 作用 |
|------|------|------|
| 语言 | Python 3.12 | 稳定、兼容性好 |
| 环境管理 | uv | 虚拟环境和依赖管理 |
| HTTP 请求 | requests + tenacity | 发送请求，自动重试 |
| JSON 解析 | 内置 json | 处理 API 响应 |
| HTML 清洗 | BeautifulSoup + lxml | 提取纯文本 |
| 配置管理 | JSON 配置文件 | 存储频道 ID |
| 增量记录 | JSON 文件 | 记录已爬取角色 ID 和名称 |

### 四、关键 API 分析

#### 4.1 角色列表 API
- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=25` (角色频道)
- **响应结构**: `data.list[0]` 为“角色”分类，其 `list` 数组包含具体角色，每个角色有 `content_id` (ID) 和 `title` (名称)。

#### 4.2 角色详情 API
- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id=<角色ID>`, `lang=zh-cn`
- **响应结构**:
  - `data.page.modules` 数组包含各个模块（基础信息、配音展示、角色宣发时间轴等）。
  - `data.page.template_layout.tab[].module_group[]` 定义了“角色描述”分组下的子模块 ID 列表（用于提取更多描述、角色故事等）。
  - 模块内容通常以 `components[0].data` 存储 JSON 字符串，内含 `rich_text` 或结构化数据。

#### 4.3 特殊 ID
- **配音展示单独 ID**: `505527`（用于旅行者，该 ID 只包含配音展示模块）

### 五、模块解析函数

每个模块对应一个解析函数，接收 `components` 列表，返回纯文本片段。

| 模块名称 | 解析函数 | 输出格式 |
|----------|----------|----------|
| 基础信息 | `parse_basic_info` | 基础信息 + 角色名 + 属性键值对 |
| 配音展示 | `parse_voice_show` | 配音展示 + 各语言语音条目 |
| 角色宣发时间轴 | `parse_role_debut` | 标题（含日期）+ 文本内容 |
| 更多描述、角色详细、角色故事等 | `parse_collapse_panel_rich_text` | 直接返回清洗后的 rich_text |

**关键代码示例**：

```python
def parse_collapse_panel_rich_text(components):
    raw_data = components[0].get("data", "{}")
    info = json.loads(raw_data)
    html_content = info.get("rich_text", "")
    return clean_html_to_text(html_content) if html_content else ""
```

### 六、增量爬取与缺失标记

- **增量记录**：使用 `config/crawled.json` 存储已爬取的角色，格式为 `{ "character": { "503613": "玛薇卡", ... } }`。
- **缺失标记**：在 `get_character_story` 中，若某模块不存在或为空，添加 `【缺失】模块名` 到输出内容。
- **文件名标记**：在 `run()` 中，若最终文本包含 `【缺失】` 或 `【待补充】`，文件名添加 `[缺失]` 前缀。

---

### 七、特殊角色处理：旅行者（主角）

- **问题**：旅行者有多个元素形态（旅行者·火、旅行者·水…），每个形态的基础信息和角色描述相同，但配音展示单独存在。
- **解决方案**：
  1. 从角色列表中过滤出所有 `旅行者·X` 条目，不单独爬取。
  2. 使用第一个旅行者条目获取基础信息和角色描述。
  3. 使用特殊 ID `505527` 获取配音展示模块。
  4. 合并内容，保存为 `旅行者.txt`，增量 ID 使用固定字符串 `traveler_main`。

### 九、常见问题与解决

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 角色描述分组未找到 | 部分角色的分组 `name` 为空，但 `module_group_id` 为 "98" | 匹配条件改为 `name=="角色描述" or module_group_id=="98"` |
| 角色登场匹配失败 | `tab_name` 包含日期前缀，如 `「2020.03.13」角色登场` | 使用 `if tab_name.endswith("角色登场")` 或 `in` 匹配 |
| 旅行者配音展示缺失 | 普通角色 API 中不含配音展示 | 单独从 ID `505527` 获取 |
| 增量记录格式升级 | 旧版只存 ID 列表，新版需存名称 | 在 `load_crawled` 中增加兼容转换：将列表转为字典 |

### 十、扩展建议

1. **支持更多模块**：根据 `template_layout` 中的其他 `module_group`（如“角色展示”、“特殊料理”等）添加解析函数。
2. **配置文件驱动**：将模块解析函数与模块 ID 的映射放入配置文件，实现动态加载。
3. **性能优化**：使用 `aiohttp` 异步并发请求，提高爬取速度。
4. **错误重试**：已有 `tenacity` 重试，可调整重试次数和延迟。
5. **日志记录**：使用 `logging` 模块替代 `print`，便于追踪和调试。
