## 装扮模块爬虫开发笔记（`outfit.py`）

> 本文档记录了《原神》观测枢装扮（衣装/风之翼/武器装扮）爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`outfit.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有装扮的详细信息，包括：
- 装扮名称、分类（衣装/风之翼/武器）
- 获取方式（游戏商城购买/活动获取/邮箱获取/任务获取/地区声望等级获取）
- **衣装**：角色信息（所属、神之眼、武器类型、命之座、生日、称号）、衣装简介、衣装故事（核心剧情文本）
- **武器装扮**：适用范围、描述、获取途径
- **风之翼**：描述、获取途径

**输出**：每个装扮保存为一个 `.txt` 文本文件，存放在 `data/cleaned/outfit/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的装扮 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。

### 三、API 分析

#### 3.1 装扮列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=211`（装扮频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "装扮"
      └── list[] → 每个装扮条目
          ├── content_id: 装扮 ID
          ├── title: 装扮名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 装扮详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={装扮ID}`, `lang=zh-cn`

#### 3.3 三种类型的详情结构对比

| 类型     | 核心模块 | 组件 ID              | 提取内容                                   |
| :------- | :------- | :------------------- | :----------------------------------------- |
| 衣装     | 衣装故事 | `collapse_panel`     | 完整剧情故事（核心）                       |
| 衣装     | 衣装简介 | `collapse_panel`     | 简短介绍                                   |
| 衣装     | 角色信息 | `dress_base_info`    | 所属、神之眼、武器类型、命之座、生日、称号 |
| 武器装扮 | 基础信息 | `material_base_info` | 描述、获取途径、适用范围                   |
| 风之翼   | 基础信息 | `material_base_info` | 描述、获取途径                             |


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含装扮的分类标签：

```json
{
  "c_211": {
    "filter": {
      "text": "[\"装扮分类/衣装\", \"衣装获取方式/游戏商城购买\"]"
    }
  }
}
```

解析后得到：
- `category`: "衣装" / "风之翼" / "武器"
- `obtain_method`: "游戏商城购买" / "活动获取" / "邮箱获取" / "任务获取" / "地区声望等级获取"

#### 4.2 衣装详情解析

**衣装故事**（核心剧情文本）：
```json
{
  "component_id": "collapse_panel",
  "data": {
    "rich_text": "<p>还能够以「少女」自称的日子里...</p>"
  }
}
```

**衣装简介**：
```json
{
  "component_id": "collapse_panel",
  "data": {
    "rich_text": "<p>茜特菈莉的装扮款式...</p>"
  }
}
```

**角色信息**（`dress_base_info`）：
```json
{
  "component_id": "dress_base_info",
  "data": {
    "attr": [
      {"key": "所属", "value": ["<p>米克特兰</p>"]},
      {"key": "神之眼", "value": ["<p>冰</p>"]},
      {"key": "武器类型", "value": ["<p>法器</p>"]}
    ]
  }
}
```

#### 4.3 武器装扮 / 风之翼详情解析

**`material_base_info` 组件**：
```json
{
  "component_id": "material_base_info",
  "data": {
    "attr": [
      {"key": "描述", "value": ["<p>「小魔女会」送给好朋友的礼物...</p>"]},
      {"key": "获取途径", "value": ["<p>参与幻友绮旅活动限时获得</p>"]}
    ],
    "materials": {
      "key": "适用范围",
      "value": "<p>仅限双手剑角色使用</p>"
    }
  }
}
```

### 六、核心函数说明

| 函数                                           | 职责                                                         |
| :--------------------------------------------- | :----------------------------------------------------------- |
| `parse_outfit_ext(ext_str)`                    | 解析 `ext.filter.text` 中的 JSON 数组，提取装扮分类和获取方式。 |
| `get_outfit_list()`                            | 获取所有装扮的 ID、名称、分类和获取方式。                    |
| `parse_outfit_detail(page_data, category)`     | 根据装扮类型（衣装/武器/风之翼）提取对应的内容。             |
| `generate_outfit_content(outfit_info, detail)` | 将装扮信息与详情数据格式化为纯文本内容。                     |
| `process_outfit(outfit, output_dir)`           | 请求详情 API，解析并保存单个装扮。                           |
| `run()`                                        | 主流程，控制爬取范围和增量逻辑。                             |

### 十、注意事项

1. **三种类型结构不同**：衣装有独立的“衣装故事”和“衣装简介”模块，武器装扮和风之翼使用 `material_base_info`。代码会根据 `category` 字段分流处理。
2. **衣装故事是核心文本**：衣装的“衣装故事”包含完整的剧情叙述，是 RAG 问答的主要文本来源，必须优先保留。
3. **无文本则跳过**：若衣装没有“衣装故事”和“衣装简介”，或武器装扮/风之翼没有“描述”，该装扮将被跳过，不生成文件。
4. **获取方式标签分组**：`衣装获取方式` 和 `风之翼获取方式` 是两组独立的标签，解析时都映射到 `obtain_method` 字段。
5. **角色信息可选**：部分衣装可能没有 `dress_base_info` 组件，缺失时跳过不影响主流程。
6. **文件名清洗**：装扮名称可能包含特殊字符（如 `「」`、`·`），使用 `safe_filename` 替换为下划线。


### 十一、与已有模块的对比

| 特性     | 装扮模块（`outfit.py`）                 | 洞天模块（`furnishing.py`）   | NPC 模块（`npc.py`）   |
| :------- | :-------------------------------------- | :---------------------------- | :--------------------- |
| 频道 ID  | `211`                                   | `130`                         | `20`                   |
| 分类标签 | 装扮分类、获取方式                      | 区域、类型、品质、获取方式    | 地区、类型、牌手挑战等 |
| 子类型   | 衣装/风之翼/武器（三种结构）            | 单一类型                      | 单一类型               |
| 核心内容 | 衣装故事/描述                           | 物品描述                      | NPC 信息、对话         |
| 特有组件 | `dress_base_info`、`material_base_info` | `cave_base_info`、`good_desc` | `npc_base_info`        |
| 输出粒度 | 每个装扮一个文件                        | 每个摆设一个文件              | 每个 NPC 一个文件      |


### 十二、后续优化方向

1. **风之翼详情确认**：目前假设风之翼与武器装扮结构相同（使用 `material_base_info`），如有差异需补充解析逻辑。
2. **获取方式细化**：当前 `obtain_method` 只取第一个匹配的标签，如果有多个获取方式（如“游戏商城购买/游戏活动获取”），可考虑保留为列表。
3. **角色信息扩展**：衣装的 `dress_base_info` 可能包含更多字段（如“称号”），当前已提取所有 `attr` 键值对，未来如有新增字段会自动适配。
4. **多版本支持**：部分衣装有多个版本（如“闲替衣装”和“活动衣装”），可考虑增加版本标记。
