## 地图文本模块爬虫开发笔记（`map_text.py`）

> 本文档记录了《原神》观测枢地图文本爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`map_text.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有地图交互文本的详细信息，包括：
- 地图文本标题、地区、分类（对话项/闪光点）、是否活动限定
- 交互文本内容（`interactive_dialogue` 中所有 `dialogue` 字段的合并文本）
- 相关任务列表（`collapse_panel` 模块）

**输出**：每个地图文本条目保存为一个 `.txt` 文本文件，存放在 `data/cleaned/map_text/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的文本 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 地图文本列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=251`（地图文本频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "地图文本"
      └── list[] → 每个地图文本条目
          ├── content_id: 文本 ID
          ├── title: 文本名称（如「关于实验【明冠山地】」）
          ├── summary: 简介/子项列表
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 地图文本详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={文本ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 关键模块：
    - `map_desc`：截图/位置图片（仅图片链接，跳过）。
    - `interactive_dialogue`：交互文本内容（核心）。
    - `collapse_panel`：相关任务列表。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含地图文本的分类标签：

```json
{
  "c_251": {
    "filter": {
      "text": "[\"地区/蒙德\", \"分类/闪光点\", \"活动限定/否\"]"
    }
  }
}
```

解析后得到：
- `region`: "蒙德"
- `category`: "闪光点"
- `is_event_only`: "否"

#### 4.2 详情页模块解析

| 模块名       | `component_id`         | 提取内容                   | 是否提取       |
| :----------- | :--------------------- | :------------------------- | :------------- |
| 地图文本标题 | `map_desc`             | 截图、位置图片（仅链接）   | ❌ 跳过         |
| 交互文本     | `interactive_dialogue` | 所有 `dialogue` 字段的文本 | ✅ 提取（核心） |
| 相关任务     | `collapse_panel`       | 关联的任务列表             | ✅ 提取         |

#### 4.3 `interactive_dialogue` 数据结构

`interactive_dialogue` 是一个对话树结构，包含多个 `dialogue` 节点：

```json
{
  "component_id": "interactive_dialogue",
  "data": {
    "list": [
      {
        "root_id": "节点ID",
        "child_ids": { ... },   // 树形结构关系
        "contents": {
          "节点ID_1": {
            "dialogue": "<p>关于实验的源起</p><p>被初代大团长封印的魔龙「乌萨」...</p>",
            "option": "",
            "icon": ""
          },
          "节点ID_2": {
            "dialogue": "<p>关于实验体的笔记</p><p>利用实验体制造恐慌的计划...</p>",
            "option": "",
            "icon": ""
          }
        }
      }
    ]
  }
}
```

**提取策略**：遍历所有 `contents` 中的节点，提取每个 `dialogue` 字段，拼接后使用 `clean_html_to_text` 清洗。

#### 4.4 相关任务结构

```json
{
  "name": "相关任务",
  "components": [
    {
      "component_id": "collapse_panel",
      "data": {
        "rich_text": "<p><strong>传说任务：</strong></p><ul><li><p>狡兔之章 第一幕「骑士之铭」</p></li></ul>"
      }
    }
  ]
}
```

提取后清洗得到任务列表文本。

### 六、核心函数说明

| 函数                                           | 职责                                                         |
| :--------------------------------------------- | :----------------------------------------------------------- |
| `get_map_text_list()`                          | 获取所有地图文本条目的 ID、名称、简介和分类标签（地区/分类/活动限定）。 |
| `parse_filter_tags(filter_text)`               | 解析 `ext.filter.text` 中的 JSON 数组，提取地区、分类、活动限定。 |
| `parse_map_text_detail(page_data)`             | 解析详情页 JSON，提取交互文本内容和相关任务。                |
| `generate_map_text_content(item_info, detail)` | 将解析结果格式化为纯文本内容。                               |
| `process_map_text(item_info, output_dir)`      | 请求详情 API，解析并保存单个地图文本条目。                   |
| `run()`                                        | 主流程，控制爬取范围和增量逻辑。                             |

### 十、注意事项

1. **`interactive_dialogue` 中的 HTML 结构多样**：包含 `<h1>`、`<p>`、`<ul>`、`<li>`、`<hr>`、`<span class="custom-entry-wrapper">` 等，`clean_html_to_text` 可以处理大部分。
2. **`custom-entry-wrapper`（引用/链接）**：在文本中会生成像 `【水仙十字之剑】` 这样的内容，`clean_html_to_text` 会保留纯文本，效果良好。
3. **对话树中的重复内容**：同一个对话节点可能在不同分支中出现，提取时直接拼接所有 `dialogue` 即可，无需去重。
4. **空内容处理**：有些地图文本可能只包含图片或空对话，这类条目应跳过。
5. **图片链接舍弃**：`map_desc` 模块仅包含截图和位置图片的链接，无文本价值，已跳过。
6. **相关任务模块**：并非所有地图文本都有 `相关任务` 模块，代码中有空值判断，无则跳过。
7. **文件名清洗**：地图文本名称可能包含 `【】`、`·` 等特殊字符，使用 `safe_filename` 仅替换 Windows 非法字符（`\ / : * ? " < > |`），其他字符保留。


### 十一、与已有模块的对比

| 特性     | 角色/武器/敌人                | 地图文本                              |
| :------- | :---------------------------- | :------------------------------------ |
| 频道 ID  | 5, 6, 25, 218, 255            | **251**                               |
| 分类标签 | 类型、元素、星级等            | **地区、分类、活动限定**              |
| 核心组件 | `good_desc`、`collapse_panel` | **`interactive_dialogue`**            |
| 核心字段 | 背景故事、技能描述、数值      | **所有 `dialogue` 字段**              |
| 内容特征 | 长文本（故事、描述）          | **长短不一**（从一句话到多段文字）    |
| 数据用途 | RAG 语料库（角色/剧情知识）   | **RAG 语料库**（世界细节、背景 lore） |


### 十二、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围和模式。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
4. **提取更细粒度的对话关系**：目前仅合并所有 `dialogue` 文本，未来可考虑保留对话树结构，用于更复杂的对话分析。
