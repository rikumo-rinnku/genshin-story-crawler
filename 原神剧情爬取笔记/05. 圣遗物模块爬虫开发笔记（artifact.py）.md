## 圣遗物模块爬虫开发笔记（`artifact.py`）

> 本文档记录了《原神》观测枢圣遗物爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。

---

### 一、模块概述

**模块名称**：`artifact.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有圣遗物套装的详细信息，包括：
- 套装名称、星级、获取途径
- 2件套/4件套效果
- 五个部件（生之花、死之羽、时之沙、空之杯、理之冠）的名称、描述和背景故事（核心）

**输出**：每个圣遗物套装保存为一个 `.txt` 文本文件，存放在 `data/cleaned/artifact/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的套装 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 圣遗物列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=218`（圣遗物频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "圣遗物"
      └── list[] → 每个圣遗物套装条目
          ├── content_id: 套装 ID
          ├── title: 套装名称
          ├── summary: 简介（如「月之七」版本新圣遗物 天之美赐）
          └── ext: 包含星级、获取方式、套装效果的 JSON 字符串
  ```

#### 3.2 圣遗物详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={套装ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 关键模块：
    - `rich_base_info`：基础信息（与列表重复，跳过）。
    - `artifact_list_v2`：部件数据（名称、描述、故事）。
    - `multi_table`：搭配推荐（纯攻略，跳过）。

### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含圣遗物的筛选标签和套装效果：

```json
{
  "c_218": {
    "filter": {
      "text": "[\"星级/五星\", \"星级/四星\", \"获取方式/秘境\", \"获取方式/深境螺旋\"]"
    },
    "table": {
      "list": [
        { "key": "2件套", "value": "元素充能效率提高20%。" },
        { "key": "4件套", "value": "若装备者已经完成了魔女的课业..." }
      ]
    }
  }
}
```

解析后得到：
- `star`: 五星
- `source`: ["秘境", "深境螺旋"]
- `set_2`: "元素充能效率提高20%。"
- `set_4`: "若装备者已经完成了魔女的课业..."

#### 4.2 详情页部件提取

圣遗物详情页最核心的内容是五个部件的背景故事，每个部件对应一个 `artifact_list_v2` 模块：

| 模块名 | 部件名称字段    | 描述字段        | 故事字段         |
| ------ | --------------- | --------------- | ---------------- |
| 生之花 | `name.value[0]` | `desc.value[0]` | `story.value[0]` |
| 死之羽 | `name.value[0]` | `desc.value[0]` | `story.value[0]` |
| 时之沙 | `name.value[0]` | `desc.value[0]` | `story.value[0]` |
| 空之杯 | `name.value[0]` | `desc.value[0]` | `story.value[0]` |
| 理之冠 | `name.value[0]` | `desc.value[0]` | `story.value[0]` |

#### 4.3 跳过模块

| 模块名   | `component_id`   | 跳过原因                  |
| -------- | ---------------- | ------------------------- |
| 基础信息 | `rich_base_info` | 与列表数据重复            |
| 搭配推荐 | `multi_table`    | 纯攻略内容，对 RAG 无帮助 |

### 六、核心函数说明

| 函数                                               | 职责                                                   |
| -------------------------------------------------- | ------------------------------------------------------ |
| `get_artifact_list()`                              | 获取所有圣遗物套装的 ID、名称、summary 和 ext 元数据。 |
| `parse_ext_info(ext_str)`                          | 解析 `ext` 字段，提取星级、获取方式、2件套/4件套效果。 |
| `parse_artifact_detail(page_data)`                 | 解析详情页 JSON，提取五个部件的名称、描述、故事。      |
| `process_artifact_with_info(artifact, output_dir)` | 请求详情 API，解析并保存单个圣遗物套装。               |
| `run()`                                            | 主流程，控制爬取范围和增量逻辑。                       |

### 十、增量机制

使用 `crawled.json` 记录已爬取的圣遗物套装 ID，格式：

```json
{
  "artifact": {
    "508651": "天之美赐",
    "508652": "影中沉凝的幻灭"
  }
}
```

- 每次运行，先调用 `is_crawled("artifact", aid)` 检查。
- 若已存在，跳过；否则请求详情并保存，成功后调用 `mark_crawled("artifact", aid, aname)`。
- 若官方更新内容，需手动从 `crawled.json` 的 `artifact` 对象中删除对应 ID。

### 十二、注意事项

1. **部件名称**：部件名称可能包含特殊字符（如 `·`），但 `safe_filename` 仅替换 Windows 非法字符（`\ / : * ? " < > |`），其他字符保留，文件名安全。
2. **故事文本清洗**：`story` 字段通常包含诗歌格式的文本，`clean_html_to_text` 会保留换行，适合阅读。
3. **重复内容**：基础信息（稀有度、获取途径、套装效果）在列表和详情页重复，已统一从列表提取，避免冗余。
4. **搭配推荐**：纯攻略内容，对 RAG 问答无帮助，已跳过。
5. **网络超时**：如遇 SSL 超时，可检查网络连接或增加 `timeout` 参数。

### 十三、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
4. **部件顺序保证**：当前按固定顺序（生之花→死之羽→时之沙→空之杯→理之冠）输出，若 API 返回顺序变化，可进一步优化。
