## 📘 武器模块爬虫开发笔记（`weapon.py`）

> 本文档记录了《原神》观测枢武器爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。

---

### 一、模块概述

**模块名称**：`weapon.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有武器的详细信息，包括：
- 武器基础信息（名称、类型、星级）
- 武器技能效果描述
- 武器背景故事（相关故事）
- 获取途径

**输出**：每个武器保存为一个 `.txt` 文本文件，存放在 `data/cleaned/weapon/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的武器 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了武器内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 武器列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=5`（武器频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "武器"
      └── list[] → 每个武器条目
          ├── content_id: 武器 ID
          ├── title: 武器名称
          └── ext: 包含星级、类型、属性加成、获取途径的 JSON 字符串
  ```

#### 3.2 武器详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={武器ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - `template_layout.tab`：定义页面布局，但武器模块结构简单，可直接遍历 `modules` 提取。

### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含武器的筛选标签，用于快速提取元数据：

```json
{
  "c_5": {
    "filter": {
      "text": "[\"武器星级/五星\", \"武器类型/长柄武器\", \"属性加成/暴击率\", \"获取途径/祈愿\"]"
    }
  }
}
```

解析后得到：
- `star`: 五星
- `category`: 长柄武器
- `attributes`: ["暴击率"]
- `source`: ["祈愿"]

#### 4.2 详情页模块解析

| 模块名   | `component_id`          | 提取内容                         | 是否提取           |
| -------- | ----------------------- | -------------------------------- | ------------------ |
| 无名     | `equipment_base_info`   | 武器名称、类型、星级             | ✅ 提取             |
| 装备描述 | `good_desc`             | 技能名称、技能描述、获取途径     | ✅ 提取             |
| 成长数值 | `equipment_growth_info` | 各等级属性、突破材料             | ❌ 跳过（纯数值）   |
| 相关故事 | `collapse_panel`        | **武器背景故事（核心剧情语料）** | ✅ **重点提取**     |
| 推荐角色 | `multi_table`           | 推荐角色列表                     | ❌ 跳过（通常为空） |
| 装备展示 | `map_desc`              | 武器外观 GIF                     | ❌ 跳过（图片）     |

#### 4.3 技能描述提取

`good_desc` 中的 `rich_text` 包含技能的完整描述，包括：
- 精炼等级说明
- 技能效果
- 触发条件

经 `clean_html_to_text` 清洗后获得纯文本。

#### 4.4 相关故事提取

`collapse_panel` 中的 `rich_text` 包含武器的背景故事（lore），是 RAG 项目最需要的文本内容。

### 六、核心函数说明

| 函数                                                 | 职责                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------ |
| `get_weapon_list()`                                  | 获取所有武器的 ID、名称和 ext 元数据。                       |
| `parse_ext_info(ext_str)`                            | 解析 `ext` 字段，提取星级、类型、属性加成、获取途径。        |
| `parse_weapon_detail(page_data)`                     | 解析武器详情页 JSON，提取名称、类型、星级、技能、故事、获取途径。 |
| `process_weapon(weapon_id, weapon_name, output_dir)` | 请求详情 API，解析并保存单个武器。                           |
| `run()`                                              | 主流程，控制爬取范围和增量逻辑。                             |

### 十、增量机制

使用 `crawled.json` 记录已爬取的武器 ID，格式：

```json
{
  "weapon": {
    "508805": "灾悔",
    "508913": "超越之匙"
  }
}
```

- 每次运行，先调用 `is_crawled("weapon", wid)` 检查。
- 若已存在，跳过；否则请求详情并保存，成功后调用 `mark_crawled("weapon", wid, wname)`。
- 若官方更新内容，需手动从 `crawled.json` 的 `weapon` 对象中删除对应 ID。

---

### 十一、注意事项

1. **技能描述中的精炼数值**：当前保留完整的技能描述文本，包含精炼 1~5 阶数值。若后续 RAG 不需要数值，可在 `parse_weapon_detail` 中进一步清洗。
2. **跳过模块**：成长数值、突破材料、推荐角色、装备展示均被跳过，因为这些内容对剧情问答无帮助。
3. **武器名称特殊字符**：武器名称中可能包含 `「」`、`·` 等字符，`safe_filename` 已处理，仅替换 Windows 非法字符（`\ / : * ? " < > |`），其他字符保留。
4. **网络超时**：如遇 SSL 超时，可检查网络连接或增加 `timeout` 参数。

---

### 十二、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
