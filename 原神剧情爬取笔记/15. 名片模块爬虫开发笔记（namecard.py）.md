## 名片模块爬虫开发笔记（`namecard.py`）

> 本文档记录了《原神》名片爬虫模块的设计思路、API 分析、数据结构解析和实现细节。该模块是项目中唯一使用**第三方 Wiki 数据源**的模块，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`namecard.py`  
**数据源**：Bilibili Wiki（`https://wiki.biligame.com/ys/名片`）

**功能**：爬取所有名片的详细信息，包括：
- 名片名称（如「阿贝多·阳花」）
- 类型（角色好感名片/纪行名片/活动名片等）
- 获取方式（好感度礼包/纪行/活动等）
- 介绍文本（名片的描述文字）
- 实装版本（1.0 ~ 5.x）

**输出**：每张名片保存为一个 `.txt` 文本文件，存放在 `data/cleaned/namecard/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的名片 ID（`pageid`）。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。

### 三、数据源分析

#### 3.1 为什么使用第三方 Wiki？

官方观测枢的“名片”频道（`channel_id=2`）**只包含图片，没有文本内容**，无法提取描述和获取方式等文本信息。因此转向数据更完整的 Bilibili Wiki。

#### 3.2 MediaWiki API

Bilibili Wiki 基于 MediaWiki 引擎，提供标准的 **Action API**：

| API 端点                            | 用途                           |
| :---------------------------------- | :----------------------------- |
| `action=query&list=categorymembers` | 获取“名片”分类下的所有页面列表 |
| `action=parse&pageid={id}`          | 获取指定页面的解析后 HTML 内容 |

#### 3.3 列表 API 响应结构

```
query.categorymembers[]
  ├── pageid: 页面 ID（用于详情请求）
  └── title: 名片名称（如「阿贝多·阳花」）

continue.cmcontinue → 分页游标（用于获取下一页）
```

#### 3.4 详情 API 响应结构

```
parse.text.* → 页面 HTML
  └── <table class="wikitable">
        ├── 类型
        ├── 获取方式
        ├── 介绍
        └── 实装版本
```


### 四、数据结构与解析逻辑

#### 4.1 名片列表获取（支持分页）

MediaWiki API 默认每页返回 10 条结果，通过 `cmlimit=500` 可提升至 500 条/页。但 279 张名片仍需要分页，使用 `cmcontinue` 游标实现：

```python
params = {
    "action": "query",
    "list": "categorymembers",
    "cmtitle": "Category:名片",
    "cmlimit": "500",
    "format": "json"
}

while True:
    resp = requests.get(WIKI_API_URL, params=params).json()
    cards.extend(resp["query"]["categorymembers"])
    if "continue" not in resp:
        break
    params["cmcontinue"] = resp["continue"]["cmcontinue"]
```

#### 4.2 名片详情解析

详情页的 HTML 表格结构：

```html
<table class="wikitable">
  <tr><th colspan="3">阿贝多·阳花</th></tr>
  <tr><th>类型</th><td>角色好感名片</td></tr>
  <tr><th>获取方式</th><td>阿贝多 好感度10级礼包获取。</td></tr>
  <tr><th>介绍</th><td>请让我来当这项奇迹的见证者吧。</td></tr>
  <tr><th>实装版本</th><td>1.2</td></tr>
</table>
```

解析时遍历表格行，根据 `th` 标签的文本匹配字段：

| 表头     | 提取字段      | 是否保留  |
| :------- | :------------ | :-------- |
| 类型     | `type`        | ✅         |
| 获取方式 | `obtain`      | ✅         |
| 介绍     | `description` | ✅（核心） |
| 实装版本 | `version`     | ✅         |

#### 4.3 特殊说明

- **无介绍则跳过**：如果某张名片没有“介绍”文本（可能是占位页面），视为无价值内容，该名片被跳过，不生成文件。
- **获取方式可能为空**：部分名片获取方式为空白，正常保留为空字符串。


### 五、输出格式

每张名片保存为一个 `.txt` 文件，文件名使用名片名称（非法字符替换为 `_`）。

**内容结构示例**（以“阿贝多·阳花”为例）：

```
名片名称：阿贝多·阳花
类型：角色好感名片
实装版本：1.2
获取方式：阿贝多 好感度10级礼包获取。

【介绍】
请让我来当这项奇迹的见证者吧。
```


### 六、核心函数说明

| 函数                                               | 职责                                                         |
| :------------------------------------------------- | :----------------------------------------------------------- |
| `get_all_cards()`                                  | 使用 MediaWiki API 获取所有名片的 `pageid` 和 `title`，支持分页自动翻页。 |
| `parse_namecard_detail(html_content)`              | 从名片页面的 HTML 表格中解析类型、获取方式、介绍、实装版本。 |
| `get_card_detail(pageid)`                          | 请求名片详情页 HTML，调用 `parse_namecard_detail` 解析。     |
| `generate_namecard_content(namecard_info, detail)` | 将名片信息和详情格式化为纯文本内容。                         |
| `process_namecard(namecard, output_dir)`           | 获取详情并保存单个名片。                                     |
| `run()`                                            | 主流程，控制爬取范围和增量逻辑。                             |

### 十、注意事项

1. **数据源差异**：本模块使用第三方 Wiki（Bilibili Wiki），而非官方观测枢 API。Wiki 页面可能由玩家编辑，内容准确性与官方 API 有差异。
2. **请求频率控制**：每次请求间隔 0.5~2 秒，避免触发反爬机制。
3. **无介绍则跳过**：若名片页面没有“介绍”文本，视为无价值内容，该名片被跳过。
4. **分页处理**：名片列表超过 500 条时需要处理 `cmcontinue` 游标，代码已自动处理。
5. **异常处理**：部分 `pageid` 可能已被删除或重定向，代码会捕获异常并跳过。
6. **文件名清洗**：名片名称可能包含特殊字符（如 `·`、`「」`），使用 `safe_filename` 替换为下划线。
7. **增量爬取**：使用 `crawled.json` 记录已爬取的 `pageid`，避免重复请求。


### 十一、与已有模块的对比

| 特性                  | 名片模块（`namecard.py`）     | 现有模块（`npc.py` / `domain.py` 等） |
| :-------------------- | :---------------------------- | :------------------------------------ |
| 数据源                | Bilibili Wiki（第三方）       | 米哈游观测枢（官方）                  |
| 列表 API              | MediaWiki `categorymembers`   | 官方 `content/list`                   |
| 详情 API              | MediaWiki `parse`             | 官方 `entry_page`                     |
| 响应格式              | HTML（需 BeautifulSoup 解析） | JSON（直接解析）                      |
| 是否需要 `channel_id` | ❌ 不需要                      | ✅ 需要                                |
| 分类标签              | 无（按分类获取）              | `ext.filter.text`                     |
| 输出粒度              | 每张名片一个文件              | 每个条目一个文件                      |


### 十二、后续优化方向

1. **支持官方数据源**：如果米哈游官方观测枢为“名片”频道增加了文本内容，可切换回官方 API。
2. **更健壮的表格解析**：部分名片的 HTML 表格结构可能有变化（如新增“备注”行），当前解析逻辑只匹配固定字段，可改为按行号或更灵活的匹配方式。
3. **获取方式中的链接提取**：当前使用 `get_text(strip=True)` 提取纯文本，未来可考虑保留链接文本或提取链接目标。
4. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
