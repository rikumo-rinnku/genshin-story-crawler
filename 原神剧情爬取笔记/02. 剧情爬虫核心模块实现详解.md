# 核心模块与统一约定

> 本文以当前 `src/core/` 实现为准。模块开发应复用这些能力，避免复制请求、存储或发布逻辑。

## `client.py`：可重试 JSON 请求

`get()` 与 `post()` 使用 `requests` 请求、30 秒默认超时和 `tenacity` 指数退避重试（最多 3 次）。除了 `raise_for_status()`，请求层还会调用 `resp.json()` 验证正文。

这样可处理上游偶发的“HTTP 200 但 JSON 被截断或不完整”问题：解析异常会回到重试机制，而不是在模块解析阶段直接失败。调用方仍需检查业务层 `retcode` 和数据结构。

## `parser.py`：HTML 转纯文本

`clean_html_to_text()` 使用 BeautifulSoup 和 lxml 去除 HTML 标记、压缩空行，并保留段落换行。模块应在写入正文前使用它清理富文本字段；不要把原始 HTML 直接交给 RAG。

## `storage.py`：本机增量状态

`config/crawled.json` 记录 `{module: {entry_id: title}}`，旧版数组格式可兼容读取。常用接口：

- `is_crawled(module, entry_id)`：判断默认增量是否跳过。
- `mark_crawled(module, entry_id, title)`：仅在正文成功写入后标记。
- `save_text()`：历史兼容接口；新模块不得用它作为正式 RAG 发布方式。

该文件是运行缓存，不能作为数据集唯一事实来源，也不提交到 Git。

## `dataset.py`：稳定语料与发布

`save_document(content, module, entry_id, title, section_id=...)` 会写入稳定 ID 文件名，以 `doc_id` 为主键登记至 `data/manifest.sqlite3`，同时记录标题、来源、写入时间和正文 SHA-256。

`publish_manifest()` 从 SQLite 导出 `data/manifest.jsonl`。在完整更新后，也可执行 `scripts/build_manifest.py --strict` 重建并发现旧文件身份问题。正式入库前必须运行 `scripts/validate_dataset.py`。

## `runtime.py` 与 `config_loader.py`

`runtime.py` 提供项目根目录、数据目录、日志目录及模块报告写入；`config_loader.py` 从已跟踪的 `config/channels.json` 读取频道 ID。不要在模块内散落频道号或依赖当前工作目录的相对路径。

## 统一模块骨架

```text
获取频道列表 → 提取 ID/标题/筛选信息 → 跳过已抓取条目
→ 获取详情页 → 解析组件 → 生成可读纯文本
→ save_document → mark_crawled → 返回统计
```

统计中应区分 `processed`、`skipped` 与带 ID、标题、原因的 `failed`；只有正文写入成功后才能标记已抓取。
