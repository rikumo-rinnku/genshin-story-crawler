# 任务剧情模块维护笔记

> 对应 `src/modules/task.py`。任务是分段语料：一个官方任务条目可产生多份子任务正文。

## 输入与身份

- 目录：观测枢频道 `task`（由 `config/channels.json` 提供）。
- 详情：`/hoyowiki/genshin/wapi/entry_page?app_sn=ys_obc&entry_page_id=<id>&lang=zh-cn`。
- 正文：`data/cleaned/task/<task_id>__<group_id>.txt`。
- `doc_id`：`task:<task_id>:<group_id>`；标题只是子任务展示名。

## 解析规则

模块读取任务概述、任务过程和剧情对话等组件，并排除“地图说明”“任务奖励”等不属于子任务正文的组。正文包含任务名称、类型、地区、版本号和各模块文本。

`interactive_dialogue` 同时支持两种官方结构：新版对话树位于 JSON 的 `list`；旧版将根节点、`child_ids`、`contents` 直接置于顶层。遍历时保留选项和台词，并用已访问集合防止环引用。此前 7062 等旧任务缺少对话，根因正是未兼容旧版顶层结构；修复后不得回退为只读取 `list`。

## 更新与修复

普通增量会跳过 `config/crawled.json` 中已有任务。发现某个任务正文缺段时，使用：

```powershell
python scripts/repair_task_dialogues.py 7062
python scripts/repair_task_dialogues.py --all-from-crawled
```

修复完成后执行 Manifest 构建与校验。不要只删除 `crawled.json` 条目而不检查旧分段文件，否则可能留下重复或过时正文。

## 质量检查

- 任务存在子任务，但某段没有 `【剧情对话】` 时，先核对官方接口中对应组件。
- `logs/crawl_report.json` 的 `missing` 和 `failed` 是人工复核入口。
- 同一 `task_id + group_id` 只能有一份 Manifest 记录；RAG 以分段 `doc_id` 入库。
