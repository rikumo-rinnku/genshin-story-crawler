## 📘 《原神》剧情文本爬虫项目 - 设计说明文档

> 版本：v1.0  
> 最后更新：2026-06-10  
> 目标：为 RAG 问答系统提供可增量更新的《原神》官方剧情语料

---

### 一、项目目标

从米哈游官方观测枢 Wiki（https://baike.mihoyo.com/ys/）中爬取所有剧情相关文本（角色故事、任务对话、书籍、活动剧情等），清洗后保存为纯文本文件，供后续 RAG 知识库构建使用。要求支持游戏版本更新时的**增量爬取**（只抓新增条目，避免重复）。

---

### 二、技术栈与工具

| 类别      | 工具                      | 作用                                              |
| --------- | ------------------------- | ------------------------------------------------- |
| 环境管理  | **uv**                    | 创建虚拟环境，管理 Python 依赖，替代 pip+venv     |
| 语言      | **Python 3.12**           | 稳定、兼容性好                                    |
| HTTP 请求 | **requests**              | 获取静态页面或 JSON API                           |
| HTML 解析 | **BeautifulSoup4 + lxml** | 从页面中提取剧情文本                              |
| 动态渲染  | **Playwright**            | 处理 JavaScript 动态加载的内容（备用）            |
| 数据存储  | **JSON**                  | 记录已爬取条目标识（增量控制）                    |
| 最终输出  | **纯文本 .txt**           | 每个条目一个文件，或按模块合并，便于 RAG 直接使用 |

---

### 三、架构设计

采用 **分层 + 模块化** 结构，避免代码重复，同时保持各模块独立性。

```
genshin-story-crawler/
├── src/
│   ├── core/
│   │   ├── __init__.py      
│   │   ├── client.py      # 统一请求（重试、头、代理）
│   │   ├── parser.py     # 公共清洗工具（去除HTML标签、提取纯文本）
│   │   └── storage.py          # 保存文本、管理 crawled.json
│   ├── modules/
│   │   ├── character.py        # 角色剧情爬取
│   │   ├── enemy.py            # 敌人/怪物剧情
│   │   ├── activity.py         # 活动剧情
│   │   ├── task.py             # 任务剧情
│   │   ├── book.py             # 书籍文本
│   │   └── ...                 # 按需扩展
│   └── runner.py               # 统一调度器，根据配置文件运行指定模块
├── data/
│   ├── raw/                    # 保留原始响应（可选）
│   ├── cleaned/                # 清洗后的 txt 文件（按模块/条目存放）
│   └── crawled.json            # 已爬取记录 { module: [entry_id, ...] }
├── scripts/
│   └── run_crawler.py          # 入口脚本，调用 runner
├── pyproject.toml              # uv 依赖清单
└── README.md
```

### 四、核心流程（以角色模块为例）

1. **获取角色列表**  
   - 方法：请求官方 API 或解析列表页 HTML。  
   - 输出：角色名称 + 详情页 URL / 角色 ID。

2. **增量检查**  
   - 读取 `data/crawled.json` 中 `character` 列表。  
   - 若角色名已存在，跳过；否则进入下一步。

3. **获取角色详情**  
   - 请求详情页或 API，获取包含剧情文本的 HTML/JSON。

4. **解析剧情文本**  
   - 使用 `BeautifulSoup` 提取目标 div（如 `.story-content`），去除标签，保留纯文本。
   - 若内容为 JSON，直接提取文本字段。

5. **清洗与存储**  
   - 去除多余空白、统一换行符。  
   - 存储为 `data/cleaned/character/钟离.txt` 等。

6. **记录已爬取**  
   - 将角色名追加到 `crawled.json` 中的 `character` 数组并保存。

---

### 五、增量爬取策略

- **仅根据条目名称/ID 去重**：假设官方只增加新内容，极少修改旧文本。  
- **记录文件**：`crawled.json` 按模块存储已爬取的条目标识。  
- **更新版本**：游戏版本更新后，再次运行爬虫，会自动跳过已有条目，只处理新增内容。  
- **强制重爬**：若需重新抓取（如发现内容有变），可手动删除 `crawled.json` 中对应条目或整个文件。

### 八、常见问题与建议

- **请求频率控制**：在 `http_client.py` 中加入 `time.sleep(random.uniform(1,3))`，避免被限制。  
- **User-Agent 伪装**：使用 `fake-useragent` 库随机生成。  
- **错误重试**：使用 `tenacity` 库或 `requests` 的 `adapters.Retry`。  
- **动态页面**：优先寻找 JSON API（F12 → 网络 → XHR），若无再使用 Playwright。  
- **数据质量**：清洗时保留对话、叙述文本，可酌情去除攻略性数字（如伤害倍率）。

本项目以**简洁、可维护、可扩展**为原则，使用 uv 管理环境，requests + BeautifulSoup 为主力，Playwright 为辅，通过 JSON 文件实现增量爬取。模块化设计使添加新内容类型非常容易。最终产出的纯文本文件可直接用于你的《原神》剧情 AI 项目。
