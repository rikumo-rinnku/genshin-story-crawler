# 《原神》剧情文本爬虫：项目现状与维护说明

> 文档状态：当前实现基线。本文只描述仓库已经落地的行为；接口字段或模块改动后应同步更新。

## 目标与边界

本项目从《原神》观测枢 Wiki 的目录与详情接口提取中文文本，清洗为 UTF-8 纯文本，为后续 RAG 建库提供可增量发布的语料。

- 正文以纯文本保存；Markdown 只用于维护文档，不进入语料。
- 语料身份由稳定的官方条目 ID 决定，不由中文标题、文件名或显示名称决定。
- 默认采用增量抓取；需要纠正已抓取条目时，应使用模块提供的定向或强制更新能力。
- 项目不负责向量化、检索或应用界面；AI 项目应以 Manifest 为唯一数据入口。

## 当前架构

```text
官方目录接口 → 各模块列表解析 → 官方详情接口 → 模块内容解析
                                             ↓
                                  save_document（稳定 ID 正文 + SQLite 登记）
                                             ↓
                              manifest.jsonl → RAG 增量入库

config/crawled.json ───────────→ 增量跳过控制
logs/*.log、*_report.json ─────→ 本地运行诊断
```

| 目录 | 职责 | 是否纳入版本库 |
| --- | --- | --- |
| `src/core/` | 请求、清洗、运行时、稳定语料登记 | 是 |
| `src/modules/` | 各内容类型的列表、详情与格式化逻辑 | 是 |
| `scripts/` | 构建、校验、迁移、修复和清理工具 | 是 |
| `config/channels.json` | 官方频道 ID 配置 | 是 |
| `config/crawled.json` | 本机增量状态 | 否 |
| `data/` | 本机生成的正文、Manifest、SQLite | 否 |
| `logs/` | 本机运行日志与报告 | 否 |
| `原神剧情爬取笔记/`、`docs/` | 项目知识、数据契约和交接说明 | 是 |

## 数据契约

统一写入入口是 `src.core.dataset.save_document()`：

- 普通条目：`data/cleaned/<module>/<entry_id>.txt`，`doc_id` 为 `<module>:<entry_id>`。
- 分段条目：`data/cleaned/task/<entry_id>__<section_id>.txt`，`doc_id` 追加 `:<section_id>`。
- 中文标题存入 Manifest 元数据，不参与文件命名或主键。
- `content_hash` 为正文 SHA-256；下游以 `doc_id + content_hash` 判断新增和覆盖。
- `data/manifest.jsonl` 由 SQLite 登记表发布；仅 `status=ready` 的记录可进入 RAG。

完整字段与入库规则见 `docs/rag_dataset_contract.md`；交接给 AI 项目时使用 `docs/ai_project_handoff_prompt.md`。

## 日常运行

```powershell
# 交互式选择模块
python run.py

# 无交互执行全部已注册模块
python scripts/run_incremental_all.py

# 发布并严格校验数据集
python scripts/build_manifest.py --strict
python scripts/validate_dataset.py
```

运行后先查看 `logs/run_all_report.json` 与各模块报告，再发布 Manifest。不要直接以目录扫描结果代替 Manifest。

## 维护原则

1. 新模块必须注册到 `run.py`，并使用 `save_document()`，不得再写入按标题命名的正文。
2. 目录请求和详情请求优先使用 `src.core.client.get()`；它会对 HTTP 成功但 JSON 损坏的响应触发重试。
3. 任务、地图文本、NPC 等含交互对话的模块必须兼容官方旧版顶层树和新版 `list` 包装结构。
4. 不以“已抓取”作为内容正确性的证明。遇到缺段，按条目 ID 定向重抓，再重建并校验 Manifest。
5. 清理历史标题文件前先预览；只有同哈希重复文件才可由 `cleanup_exact_legacy_duplicates.py --apply` 删除。
