## 背包物品模块爬虫开发笔记（`item.py`）

> 本文档记录了《原神》观测枢背包物品爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。


### 一、模块概述

**模块名称**：`item.py`  
**功能**：从米哈游观测枢 Wiki 爬取所有背包物品的详细信息，包括：
- 物品名称、道具类型（任务道具/食材/小道具/角色培养素材等）
- 获取方式（任务获取/活动获取/地图探索等）、星级
- 描述、用途
- 多版本变体信息（同一物品的不同来源/版本）
- 阅读内容（多章节日记、书籍等）
- 表格数据（如「森林书」中的冒险记录、曲调列表等）

**输出**：每个物品保存为一个 `.txt` 文本文件，存放在 `data/cleaned/item/` 目录下。

**增量策略**：
- 使用 `crawled.json` 记录已爬取的物品 ID。
- 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
- 若官方更新了内容，需手动从 `crawled.json` 中删除对应 ID，重新运行以更新。

### 三、API 分析

#### 3.1 物品列表 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/common/blackboard/ys_obc/v1/home/content/list`
- **参数**: `app_sn=ys_obc`, `channel_id=13`（背包频道）
- **响应结构**:
  ```
  data.data.list[0] → name: "背包"
      └── list[] → 每个物品条目
          ├── content_id: 物品 ID
          ├── title: 物品名称
          ├── summary: 简介
          └── ext: 包含分类标签的 JSON 字符串
  ```

#### 3.2 物品详情 API

- **URL**: `https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page`
- **参数**: `app_sn=ys_obc`, `entry_page_id={物品ID}`, `lang=zh-cn`
- **核心字段**:
  - `page.modules[]`：所有内容模块。
  - `modules[].components[].data`：实际数据（JSON 字符串）。
  - 关键模块：
    - `material_base_info`：物品变体信息（描述、用途、获取方式）。
    - `collapse_panel`：阅读章节（如日记、书籍正文）。
    - `multi_table`：表格数据（如「森林书」的冒险记录、曲调列表）。


### 四、数据结构与解析逻辑

#### 4.1 列表 `ext` 字段解析

`ext` 是一个 JSON 字符串，包含物品的分类标签：

```json
{
  "c_13": {
    "filter": {
      "text": "[\"道具类型/任务道具\", \"获取方式/任务获取\", \"星级/四星\"]"
    }
  }
}
```

解析后得到：
- `item_type`: "任务道具"
- `obtain`: "任务获取"
- `star`: "四星"

#### 4.2 详情页模块解析

| 模块名   | `component_id`       | 提取内容                    | 是否提取 |
| :------- | :------------------- | :-------------------------- | :------- |
| 变体信息 | `material_base_info` | 名称、描述、用途、获取方式  | ✅ 提取   |
| 阅读章节 | `collapse_panel`     | 多章节文本（日记/书籍正文） | ✅ 提取   |
| 表格数据 | `multi_table`        | 多标签页的表格文案          | ✅ 提取   |

#### 4.3 `material_base_info` 数据结构

每个 `material_base_info` 模块代表一个变体：

```json
{
  "name": "「木偶」的笔记本",
  "star": 4,
  "materials": {
    "key": "获取方式",
    "value": "<p>完成空月之歌 第八幕「真实之月」后，在【旗舰】酒馆旅行者的房间处拾取</p>"
  },
  "attr": [
    {"key": "描述", "value": ["<p>由「仆人」转交给你的，桑多涅的遗物...</p>"]},
    {"key": "用途", "value": ["<p>交付枫丹世界任务往事追迹</p>"]}
  ]
}
```

#### 4.4 `collapse_panel` 阅读章节

部分物品（如「木偶」的笔记本）包含多个阅读章节：

```json
{
  "name": "阅读（1/9）",
  "components": [
    {
      "component_id": "collapse_panel",
      "data": {
        "rich_text": "<p>■月■日  晴</p><p>阿兰给过我很多笔记本...</p>"
      }
    }
  ]
}
```

**提取策略**：遍历所有 `collapse_panel` 模块，提取 `rich_text`，按模块名分段合并。

#### 4.5 `multi_table` 表格数据

部分物品（如「森林书」）包含多标签页表格：

```json
{
  "component_id": "multi_table",
  "data": {
    "tables": [
      {
        "tab_name": "森林冒险记录",
        "header": ["故事", "插图", "文案"],
        "row": [
          ["林中奇遇", "<img...>", "从兰罗摩手中拿到了这本「森林书」..."],
          ["梦中的苗圃", "<img...>", "与兰罗摩在桓那兰那一起干了一些..."]
        ]
      }
    ]
  }
}
```

**提取策略**：遍历所有 `tables`，提取每个 `tab_name` 下的所有 `row` 中的**文案列**（通常为最后一列），合并标题和内容。

#### 4.6 文本换行压缩

描述、用途、获取方式等短文本中，`clean_html_to_text` 会将内联标签之间的文本用换行分隔，导致句子破碎。使用 `clean_text_compact` 函数将其压缩为单行：

```python
def clean_text_compact(text: str) -> str:
    """将多行文本压缩为单行，去除多余换行和空白"""
    if not text:
        return ""
    return " ".join(text.split())
```

**示例**：
- 压缩前：`"向NPC【埃尔西】交付三本书籍后，可以获得\n大英雄的经验\n*2\n、\n摩拉\n*20000"`
- 压缩后：`"向NPC【埃尔西】交付三本书籍后，可以获得大英雄的经验*2、摩拉*20000"`

### 六、核心函数说明

| 函数                                       | 职责                                                         |
| :----------------------------------------- | :----------------------------------------------------------- |
| `get_item_list()`                          | 获取所有物品的 ID、名称、简介和分类标签（道具类型/获取方式/星级）。 |
| `parse_filter_tags(filter_text)`           | 解析 `ext.filter.text` 中的 JSON 数组，提取道具类型、获取方式、星级。 |
| `extract_materials_text(html)`             | 从获取方式的 HTML 中提取紧凑格式的纯文本。                   |
| `clean_text_compact(text)`                 | 将多行文本压缩为单行，去除多余换行和空白。                   |
| `parse_item_detail(page_data)`             | 解析详情页 JSON，提取变体信息、阅读内容和表格数据。          |
| `generate_item_content(item_info, detail)` | 将解析结果格式化为纯文本内容。                               |
| `process_item(item_info, output_dir)`      | 请求详情 API，解析并保存单个物品。                           |
| `run()`                                    | 主流程，控制爬取范围和增量逻辑。                             |

### 十、注意事项

1. **获取方式以详情页为准**：列表页的 `ext` 中虽包含获取方式，但详情页 `materials.value` 更详细、更准确，因此输出时以详情页为准，列表页的获取方式不输出。
2. **文本换行压缩**：描述、用途、获取方式等短文本中可能包含多余换行，使用 `clean_text_compact` 压缩为单行，更适合 RAG 语料库。
3. **变体数量不定**：大多数物品只有一个变体，但部分物品（如同一物品的不同来源）可能有多个，代码已支持多变体输出。
4. **阅读章节识别**：`collapse_panel` 可能是阅读章节，也可能是空的攻略模块。通过判断 `rich_text` 是否有实质内容来过滤空模块。
5. **表格数据提取**：`multi_table` 中的 `row` 数据，文案列通常为最后一列，标题为倒数第二列。提取时需根据实际列数动态判断。
6. **图片链接舍弃**：所有 `img` 字段仅包含图片链接，无文本价值，已跳过。
7. **文件名清洗**：物品名称可能包含 `「」`、`《》`、`·` 等特殊字符，使用 `safe_filename` 仅替换 Windows 非法字符（`\ / : * ? " < > |`），其他字符保留。


### 十一、与已有模块的对比

| 特性     | 食物模块                               | 背包物品模块                                                 |
| :------- | :------------------------------------- | :----------------------------------------------------------- |
| 频道 ID  | `21`                                   | `13`                                                         |
| 分类标签 | 食物类型、星级、获取方式、是否特殊料理 | **道具类型、获取方式、星级**                                 |
| 核心组件 | `material_base_info`（多个变体）       | **`material_base_info`（多变体）+ `collapse_panel`（阅读）+ `multi_table`（表格）** |
| 核心内容 | 描述、使用效果、加工材料               | **描述、用途、阅读内容、表格数据**                           |
| 特殊处理 | 加工材料换行压缩                       | **描述/用途换行压缩、多类型内容合并**                        |
| 变体判断 | 奇怪/普通/美味/特殊料理                | **不同来源/版本**                                            |


### 十二、后续优化方向

1. **支持命令行参数**：通过 `argparse` 控制爬取范围和模式。
2. **内容变更检测**：通过哈希值检测内容变化，替代手动删除 ID。
3. **多线程并发**：使用 `ThreadPoolExecutor` 加速（需控制并发数）。
4. **表格结构化提取**：目前 `multi_table` 仅提取文案文本，未来可考虑提取更结构化的表格数据（如键值对）。
5. **阅读内容章节化**：目前阅读内容按模块名分段合并，未来可考虑更精细的章节结构保留。
